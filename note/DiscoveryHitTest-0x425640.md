# 발견물 좌표 판정 — 0x425640 / 0x425720

DiscoveryEditKR(발견물 좌표 수정)을 만들며 뜯은 것이다. 요지는 **발견물 좌표는 .rdata 표
그 자리를 게임이 매번 직접 읽으므로, 실행 중에 고치면 그대로 먹는다** 는 것과,
**좌표로 찾아지는 것은 274개 중 앞 107개뿐** 이라는 것 둘이다.

## 표 — `0x0051C540` (.rdata, 92바이트 x 274)

파일오프셋 `0x11AB40`. 좌표 칸은 넷이다.

| 오프셋 | 뜻 |
|---|---|
| `+0x00` | 이름 `char*` (cp949). 문자열은 `.data` 에 있다 — 정적으로 뜯을 땐 섹션을 가려 변환할 것 |
| `+0x04` | 분류(0~7) |
| `+0x08` | 유적 번호(힌트 표와 잇는 값 — `discinst.h` 참고) |
| `+0x18` | 가치 |
| `+0x44` `+0x48` | **x1, y1** — 박스 시작 |
| `+0x4C` `+0x50` | **x2, y2** — 박스 끝 |

단위는 WORLD.CDS 를 펼친 배열의 칸 번호다(x 0~2499, y 0~1249). 함대 경도·위도
(`0x1B63B0` / `0x1B63B4`, 0~40000 / 0~20000)를 16으로 나눈 것이 그대로 이 값이다.

넷 다 `-1` 이면 "좌표로 찾는 발견물이 아니다". 원본은 274줄 중 147줄이 좌표를 가진다.

## 표를 직접 읽는 세 곳

```
0x4AAB45   mov eax, [ecx*4 + 0x51C540]     ; 이름 getter
0x425678   mov ebx, [ecx*4 + 0x51C584]     ; 0x425640 안 — 박스 판정
0x425754   mov edi, [ecx*4 + 0x51C584]     ; 0x425720 안 — 시작점 일치 판정
```

`ecx` 는 `idx*23` 이라 `*4` 하면 92바이트 스트라이드가 된다. **시작할 때 딴 데로 떠 두는
사본이 없다** — 그래서 `VirtualProtect` 로 잠깐 열고 그 4칸만 고치면 다음 판정부터 바로
새 값을 읽는다. (후원자 생년을 고치는 `patrons.c` 와 같은 수법이다.)

## 박스 판정 — `0x00425640`

```c
// 인자 (x, y). 돌려주는 것은 발견물 인스턴스 번호, 없으면 -1.
for (inst = 0x61E4C8; inst < 0x629898; inst += 0xA8) {
    i = (inst - 0x61E4C8) / 0xA8;              // 0x4AAAE0 — 그냥 나눗셈이다
    if (x < x1[i] || x > x2[i]) continue;
    if (y < y1[i] || y > y2[i]) continue;
    d = (x2[i] - x1[i]) * (x2[i] - x1[i]);
    if (best <= (unsigned)d) continue;         // best 초기값 -1 = 0xFFFFFFFF
    best = d; hit = i;
}
```

여기서 나오는 것 셋.

1. **훑는 것은 발견물 인스턴스 107개뿐이다.** `(0x629898 - 0x61E4C8) / 0xA8 = 107`.
   그리고 `0x4AAAE0` 이 인덱스를 그대로 번호로 쓰므로 **인스턴스 번호 = 발견물 번호**다.
   표는 274줄이지만 좌표로 찾아지는 것은 **0~106 뿐**이고, 107번부터는 좌표를 넣어도
   이 루프에 안 걸린다. (`discinst.c` 가 "앞 107개와 그대로 짝" 이라고 가정해 둔 것이
   맞다는 증거이기도 하다.)
2. **`-1` 을 따로 거르는 분기가 없다.** 좌표 없음이 안 걸리는 건 박스가
   `(-1,-1)~(-1,-1)` 이라 게임 좌표(0 이상)로 영영 못 맞히기 때문일 뿐이다. 그래서
   0~106 중 좌표가 `-1` 인 53개(콜로세움·파르테논 신전·스핑크스 … 죄다 유적이다)는
   좌표를 넣어 주면 그 자리에서 실제로 발견된다.
3. **겹치면 좁은 박스가 이긴다.** 고르는 잣대가 `(x2-x1)²` 의 최솟값이다. 남극대륙
   (2500 x 150)처럼 넓은 것 위에 좁은 것을 얹어도 좁은 쪽이 나온다.

`unsigned` 비교(`jbe`)라 `best` 초기값 `-1` 이 곧 "아직 아무것도 못 찾음"이다.

## 시작점 일치 판정 — `0x00425720`

같은 모양인데 비교가 `x == x1[i] && y == y1[i]` 다 — 박스가 아니라 **좌상단 점이 정확히
그 칸인 것**을 찾는다. 뒤쪽 거리 계산과 고르는 잣대는 `0x425640` 과 같다.

## 오래 가지 않는다

`.rdata` 메모리만 고치는 것이라 게임을 끄면 원래대로 돌아가고, 세이브에도 안 남는다.
DiscoveryEditKR 은 그래서 고친 값을 `CDS95Util\disc_coords.json` 에 적어 두고 다음에
뜰 때 다시 넣는다. 스키마는 WorldMapKR 의 `discoveries.json` 과 일부러 같게 뒀다 —
값을 서로 옮겨 붙일 수 있다.

```json
[ { "id": 21, "name": "콜로세움", "x1": 1512, "y1": 470, "x2": 1513, "y2": 471 } ]
```

## 지도 마커는 지도를 열 때 따라온다

WorldMapKR 의 `DiscDb_Load` 는 지도 창을 열 때(`WM_CREATE`)와 `R` 을 누를 때 불린다.
거기에 한 겹을 더 얹어, **실행 중인 게임 표에서 원본과 다른 줄만** 걷어와 맨 나중에 덮는다.

```
구운 표(kDiscCoords = 게임 원본)  ->  discoveries.json(사람이 손본 마커)  ->  고쳐진 게임 표
```

"다른 줄만" 이 요령이다. 내장 표 `kDiscCoords` 가 바로 그 게임 원본값이라, 메모리 값이
그것과 다르면 곧 "누가 실행 중에 고쳤다" 는 뜻이다. 원본 그대로인 줄까지 덮으면 사람이
`discoveries.json` 에 적어 둔 마커 보정이 지도를 열 때마다 지워진다 — 그것은 남겨야 한다.

지도 상태줄 오른쪽에 `발견물 147+게임3` 처럼 몇 줄을 게임 표에서 따라왔는지 적는다.

## 정적으로 뜯을 때 주의

이름 포인터가 `.rdata` 가 아니라 `.data` 를 가리킨다. 섹션 하나의 델타로 통째로
변환하면 이름이 죄다 깨져 나온다(그 상태로 "좌표 없는 것" 목록을 뽑았다가 엉뚱한
대사 문자열이 나왔다). PE 섹션표를 보고 VA 마다 골라 옮길 것.

| 섹션 | VA | 파일 |
|---|---|---|
| `.text` | `0x401000` | `0x400` |
| `.rdata` | `0x4C3000` | `0xC1600` |
| `.data` | `0x52F000` | `0x12C800` |

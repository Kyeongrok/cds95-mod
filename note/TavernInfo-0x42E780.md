# 술집 "정보를 듣는다" — 0x42E780 / 대사 표 0x525078

스폰서와 계약을 맺으면 술집 메뉴에 "정보를 듣는다"가 생기고, 눌러 보면 그 발견물에 대한
힌트를 들려준다. 그 길을 처음부터 끝까지 뜯은 것이다. 요지는 셋이다.

- 메뉴가 나오고 안 나오고는 **술집 객체 `+0xB8`** 하나가 가른다(`-1` 이면 항목이 없다).
- 그 값은 도시에 들어갈 때 정해지고, 뿌리는 **계약 전역 `0x61D1D0`** 이다.
- 대사는 `.rdata` 의 **24바이트 x 191 표(`0x525078`)** 에 있고, 레코드마다
  "어느 유적 이야기인지"와 "어느 도시에서 들을 수 있는지 4곳"이 붙어 있다.

## 흐름

```
계약 전역 0x61D1D0            [+0x10] = 계약된 힌트 번호
        |
        v  0x493E60
힌트 표 0x4D8E88 + h*80       [+0x00] = 유적 코드
        |
        v  0x414390           그 코드 + 지금 도시로 후보를 모은다
대사 표 0x525078 + i*24
        |
        v  0x42E780           후보 중 하나를 무작위로
술집 객체 [+0xB8]
        |
        v  0x42FE5C           >= 0 이면 "정보를 듣는다" 를 켠다
```

## 계약 전역 — `0x0061D1D0` (RVA `0x21D1D0`)

계약이 없으면 이 포인터가 0이다. `+0x10` 에 **계약된 힌트 번호**가 들어 있다.

`0x0044EE8D` 의 `mov [0x61d1d0], eax`(eax = 0)가 **비우는** 자리다 — 바로 위에서
`[0x5B619C]` 도 같이 0으로 만든다. 맺는 자리는 아직 안 봤다. 이 전역을 참조하는 코드가
92곳인데 `0x44Exxx` 에 몰려 있고, 그 언저리(`0x44E5C0`)가 시설에 들어갈 때 후원자 81명을
선형탐색하는 함수다(`patrons.c` 주석 참고). 계약 화면이 거기 있다는 뜻이다.

## 힌트 번호 -> 유적 코드 — `0x00493E60`

```c
int CodeOfContract(this)          // this = 0x61D1D0
{
    if (*(int*)this == 0) return -1;             // 계약 없음
    h = *(int*)(this + 0x10);                    // 계약된 힌트 번호
    p = (h == -1) ? NULL : (0x58B4E0 + h * 8);   // 힌트 상태 배열의 그 줄
    if (!p) return -1;
    i = 0x42CBE0(p);                             // 주소 -> 번호 역산 (sub ecx, 0x58B4E0)
    return *(int*)(0x4D8E88 + i * 80);           // 힌트 표 +0x00 = 유적 코드
}
```

`0x4D8E88` 은 `HintUtilKR/src/discinst.h` 의 `DINST_HTAB_RVA` 그 표다(80바이트 x 186).
거기 적어 둔 "발견물 표 +0x08 과 힌트 표 +0x00 이 같은 유적 번호" 가 여기서 다시 쓰인다.

## 후보 모으기 — `0x00414390`

```c
// 조건에 맞는 대사를 모은다. out 이 NULL 이면 개수만 센다.
int Collect(int city, int sphere, int code, int* out)
{
    int n = 0;
    for (i = 0; i < 191; i++) {
        rec = 0x62B1A0 + i;                     // 항목별 1바이트 배열
        for (k = 0; k < 4; k++) {
            c = 0x4B0970(rec, k);               // 이 레코드의 k 번째 도시
            if (c == -1) continue;
            obj = 0x429970(c);                  // 그 도시 객체
            if (!obj || (obj[4] & 4)) continue; // 못 쓰는 도시는 거른다
            if (city   != -1 && c != city) continue;
            if (sphere != -1 && *(int*)(obj + 0x58) != sphere) continue;   // +0x58 = 문화권
            if (code   != -1 &&
                *(int*)(0x525078 + 0x4B0960(rec) * 24) != code) continue;  // 레코드 +0x00
            if (out) out[n] = i;
            n++;
        }
    }
    return n;
}
```

도시 struct `+0x58` 이 문화권인 것은 `cds95-culture-index-runtime` 에 적어 둔 그 자리다.
`0x4B0960` 은 `0x62B1A0` 기준 인덱스 역산, `0x4B0970` 은 그 인덱스로 표에서 도시 한 칸을
꺼내는 헬퍼다.

`0x62B1A0` 은 실행 중에만 있는 **191바이트 배열**이다(표 항목 수와 같다). 헬퍼에 `&arr[i]`
를 넘기는 용도로만 쓰이는 것을 확인했고, 그 한 바이트가 무엇을 담는지는 아직 안 봤다 —
"이미 들었나" 로 짐작만 해 둔다.

## 하나를 고른다 — `0x0042E780`

```c
int PickInfo(int city)
{
    int pick = -1;
    if (!0x429970(city)) return -1;          // 도시 객체가 없다
    if (*(void**)0x61D1D0 == NULL) return -1;   // ★ 계약이 없으면 여기서 끝
    code = 0x493E60(0x61D1D0);

    n = Collect(city, -1, code, NULL);
    if (n > 0) {
        buf = malloc(n * 4);
        Collect(city, -1, code, buf);
        pick = buf[ rand() % n ];            // 0x4B7C0F
        free(buf);
        return pick;
    }
    // 이 도시에 후보가 없으면 도시를 안 가리고 다시 찾는다
    n = Collect(-1, -1, code, NULL);
    ... 같은 식 ...
    return pick;
}
```

★ **뒤쪽 갈래가 눈에 띈다.** 지금 도시에 맞는 대사가 없으면 `city = -1` 로 조건을 풀고
표 전체에서 고른다. 그래서 계약과 아무 상관 없어 보이는 도시에서도 이야기를 듣게 된다 —
버그가 아니라 "빈손으로 돌려보내지 않는다" 로 짜 둔 것이다.

## 메뉴에 켜기 — `0x0042E750` / `0x0042FDE0`

도시에 들어갈 때:

```c
void Enter(this)                       // 0x42E750
{
    this[0xB8] = 0x42E780(this[0x90]);   // +0x90 = 도시 번호
    this[0xBC] = rand();                 // 0x4B7C09
}
```

메뉴를 세우는 `0x42FDE0` 은 항목마다 12바이트(`[문자열][켜짐][?]`)를 채우고,
`jmp [eax*4 + 0x42FED0]` 점프 테이블로 항목별 처리를 고른다.

| 항목 | 문자열 | 처리 | 켜지는 조건 |
|---|---|---|---|
| 0 | 정보를 듣는다 | `0x42FE5C` | `[this+0xB8] >= 0` |
| 1 | 포카를 권한다 | `0x42FE74` | `0x42FB00` |
| 2 | 부하편성 | `0x42FE87` | `0x453CA0() > 0` |
| 3 | (NULL) | `0x42FEA3` | — |

항목 0 은 이렇게 생겼다 — `(v + 1 >= 1)` 을 `sbb` 로 0/1 로 만드는 흔한 꼴이다.

```
0042FE5C  mov eax, [esi + 0xB8]
0042FE68  inc eax
0042FE69  cmp eax, ebp        ; ebp = 1
0042FE6B  sbb eax, eax
0042FE6D  inc eax             ; v >= 0 이면 1, v == -1 이면 0
0042FE6E  mov [ecx + ebx + 4], eax
```

고른 정보를 실제로 보여주는 곳은 `0x42F93F` 다 — 같은 `[+0xB8]` 을 읽어
`0x62B1A0 + v` 를 만든다.

## 대사 표 — `0x00525078` (.rdata, 24바이트 x 191)

파일오프셋 `0x123678`.

| 오프셋 | 뜻 |
|---|---|
| `+0x00` | 유적 코드 (힌트 표 `+0x00` 과 같은 값) |
| `+0x04` `+0x08` `+0x0C` `+0x10` | 들을 수 있는 도시 4칸 (`-1` = 없음) |
| `+0x14` | 대사 `char*` (cp949) |

```
  0  code=  0  도시=[97, 99, 90]     "아프리카 남단이라고? 최남단의 곶을 발견하면 상륙해서…"
  1  code=  2  도시=[108, 109]       "이대로 북상하면 아라비아 반도가 보이네…"
  2  code=  3  도시=[155, 154, 157]  "…인도차이나에서 기다란 말레이 반도가…"
  3  code=  4  도시=[160, 161]       "향료 제도로 가려면 우선 여기서 동쪽에 있는 보르네오…"
152  code=509  도시=[206]            "카카오? 아하, 동쪽에 카카오 밭이 있네."
```

code 0/2/3/4 가 힌트 0(아프리카남단) · 2(인도항로) · 3(말라카해협) · 4(향료제도)와 그대로
맞는다. 앞쪽은 발견물 힌트, 뒤쪽(200~500번대)은 교역품·비보 이야기다.

## 고치는 것 — TavernInfoKR

`plugins-src/TavernInfoKR` 이 이 표를 실행 중에 고친다("파일 > 모드 > 술집 정보").
`.rdata` 라 `VirtualProtect` 로 잠깐 열고 **코드와 도시 4칸만** 쓴다 — 대사 포인터
(`+0x14`)는 건드리지 않으므로 `Poke` 가 여는 길이도 `TAV_TEXT_OFF` 까지다. 대사 글월
자체는 DialogUtilKR 이 하는 일이라 여기서는 읽어서 보여 주기만 한다.

고친 값은 `CDS95Util	avern_info.json` 에 적어 두고 다음에 뜰 때 다시 넣는다. 도시 칸을
비워 두면 그 칸을 안 쓰고, 가운데가 비면 게임이 그 뒤를 안 보므로 적용할 때 앞으로 몰아 준다.

## 이미 이 표를 고치고 있는 것이 있다

`CDS95Util\mods\ladyous_1.0.0\patches\06_주점힌트-카카오(메리다→미틀라).json` 이 파일
`0x1244BC` 의 한 바이트를 206 -> 204 로 바꾼다. 그 자리가 곧 **항목 152 의 도시1 칸**이고,
206 은 메리다 204 는 미틀라다. 패치 이름과 정확히 맞는다.

## 뜯을 때 걸린 것 둘

**레코드 경계.** 대사 포인터를 기준으로 24바이트를 끊었더니 대사와 도시가 한 칸씩 밀려
"차를 원한다면 천주로" 에 메리다가 붙는 식이 되었다. 코드가 `[ecx*8 + 0x525078]` 로 잡는
것을 보고서야 표 머리가 `0x525078`(유적 코드)이라는 것이 잡혔다. 표는 값이 그럴듯해도
경계가 맞는지는 **그 표를 읽는 코드에서 확인해야 한다.**

**힌트 표 주소.** `discinst.h` 의 `DINST_HTAB_RVA 0xD8E88` 은 RVA 다(VA `0x4D8E88`).
파일오프셋으로 착각해 `0xD8E88` 을 그대로 읽으면 `.text` 한복판이라 말이 안 되는 수가 나온다.
파일오프셋은 `0xD7488` 이다.

| 섹션 | VA | 파일 |
|---|---|---|
| `.text` | `0x401000` | `0x400` |
| `.rdata` | `0x4C3000` | `0xC1600` |
| `.data` | `0x52F000` | `0x12C800` |
